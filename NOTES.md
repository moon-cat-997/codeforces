| 1955D Inaccurate Subsequence Search | 1400 | two pointers | (editorial not opened — self-diagnosed after a TLE). The algorithm was right; the **cost model** was the miss. A sliding window's payoff is that only one element enters and one leaves per step, so the window's aggregate must be **maintained incrementally** (`O(1)`/step), *not* recomputed from the whole window each step. First version rebuilt the overlap `Σ min(cnt[v], b[v])` from scratch every window **and** passed both hash maps **by value** (two deep copies per call) ⇒ `O(n·m)` ≈ 10¹⁰ → TLE. Lesson: whenever a window check loops over the window's contents, that's the smell — replace it with an enter/leave delta on a running counter. Secondary: never pass containers by value into a hot loop (`const&`), and `operator[]` on a map silently inserts. Sign asymmetry to remember: enter `<`, leave `<=` |

| 1538C Number of Pairs   | 1300   | binary search  | (editorial not opened — solved from hints, 4 rewrites; logging the recurring pattern). The **idea was never the problem** — sort, fix `a[i]`, count the contiguous block of partners — the entire difficulty was **implementation**, which is a distinct skill from "find the trick". The one conceptual miss: I tried to binary-search the **band** `l ≤ sum ≤ r` directly. A band is `F…F T…T F…F` — **not monotone** — so a `false` means "left *or* right" and discards nothing. An inclusive range is always **two one-sided searches subtracted**, never one two-sided search. Three implementation slips followed: a loop body that moved only `mid` and never `lo`/`hi` (non-terminating — and `-O2` **deleted** the loop as UB, so the symptom was wrong numbers, not a hang); templates chosen by the *function's name* (`lower`/`upper`, bound backwards to `r`/`l`) instead of by the *predicate's direction*; and a closed `[lo, n-1]` interval with no way to express "no such element", which forced special cases that could not be made correct. **Pattern → habit:** write the `T`/`F` row for a tiny concrete input **before** writing the loop, phrase both edges as `F→T` so only one template exists (`> r` ≡ `≥ r+1` on integers), and always hand-roll on half-open `[lo, hi)` |
